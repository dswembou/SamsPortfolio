# Sam Developer Portfolio

Dit is het portfolio van **Sam**, een beginnende Software Developer.

In dit project oefent Sam met:

- HTML
- CSS
- JavaScript
- Git
- GitHub
- OpenCode

Het portfolio wordt tijdens de lessen stap voor stap uitgebreid.

---

## Doel van het project

Het doel van dit project is om te oefenen met het maken, organiseren, controleren en verbeteren van een eenvoudige website.

De website bevat:

- een introductie;
- informatie over Sam;
- een overzicht van projecten;
- een overzicht van vaardigheden;
- contactinformatie.

## Git gebruiken

Dit project gebruikt Git voor versiebeheer.

Enkele veelgebruikte commando's:

```text
git status
```

Laat zien welke bestanden zijn gewijzigd.

```text
git add .
```

Zet wijzigingen klaar voor een commit.

```text
git commit -m "Beschrijving van de wijziging"
```

Slaat een versie van de wijzigingen op in Git.

```text
git pull
```

Haalt de nieuwste wijzigingen van de gekoppelde remote repository op.

## Werken met OpenCode

OpenCode mag gebruikt worden als hulpmiddel tijdens het ontwikkelen.

Bijvoorbeeld om:

- code uit te leggen;
- mogelijke oorzaken van bugs te onderzoeken;
- code te reviewen;
- alternatieve oplossingen voor te stellen.

De belangrijkste regels zijn:

> **Begrijp het.**

> **Controleer het.**

> **Jij beslist.**

Gebruik dus geen code alleen omdat OpenCode zegt dat deze goed is.

---

## Debuggen

Wanneer iets niet werkt, pas dan niet direct meerdere dingen tegelijk aan.

Gebruik deze werkwijze:

1. **Observeren** – Wat werkt er niet?
2. **Hypothese** – Wat zou de oorzaak kunnen zijn?
3. **Onderzoeken** – Controleer code, bestanden, paden en foutmeldingen.
4. **Aanpassen** – Verander één ding.
5. **Testen** – Controleer of het probleem opgelost is.

OpenCode kan helpen bij het onderzoeken, maar probeer eerst zelf te begrijpen wat er misgaat.

## Bekende situatie

De website is gemaakt als oefenproject.

Tijdens sommige lessen kunnen er bewust fouten in het project staan.

Dat betekent niet automatisch dat je direct alle code moet laten repareren.

Onderzoek eerst:

> **Wat zie ik?**

> **Waar kan de oorzaak zitten?**

> **Hoe kan ik dit testen?**
